# 36 套排版主题视觉审计

一轮**只审计、不改代码**的逐套体检。36 套主题全部在 375px（公众号真实阅读宽度）下渲染同一份样张并截图，逐张肉眼评分，配合静态 CSS 统计和计算样式测量交叉验证。

## 审计方法

| 项目 | 说明 |
| --- | --- |
| 截图脚本 | `scripts/audit-theme-visuals.mjs`（CDP 连 dev server，逐套 `applyTheme` + 注入统一样张 + 全页截图） |
| 静态分析 | `scripts/audit-theme-css.mjs`（覆盖度、伪元素、标题手法、配色组织、结构相似度） |
| 剪贴板验证 | `scripts/audit-theme-clipboard.mjs`（伪元素装饰和 CSS 计数器能否活着穿过复制管线） |
| 截图产物 | `/tmp/theme-audit/<theme>.png`（375px 单栏原尺寸）、`/tmp/theme-audit/sheet/<theme>.png`（三栏拼版，便于并排比对） |
| 样张内容 | h1–h4、多段正文、粗体/斜体/行内代码/链接、无序与有序列表、引用块、代码块、表格、分割线、图片＋图注、GFM NOTE 与 WARNING 提示块 |
| 运行参数 | 产品出厂默认值：`primaryColor: #2851E3`、`fontSize: 14px`、`fontFamily: PingFang SC`，未开启标题预设样式（否则会盖掉主题自己的标题设计） |

**截图结果：36 / 36 全部成功**，没有渲染异常或注入被覆盖的情况。单栏图高度 1990–2262px，说明各主题的整体密度差异在 ±7% 以内。

评分为四维各 1–5 分，综合分 = 视觉精致度 ×0.3 + 辨识度 ×0.3 + 完成度 ×0.2 + 公众号适配 ×0.2。

**综合结论的判定规则**（不是单纯看分数）。满足以下任意一条即进入砍掉候选：

1. **执行不合格**：综合分 < 2.8
2. **结构重复**：辨识度 ≤ 2，且与另一套主题的结构相似度 ≥ 80%——重复就砍，哪怕单看它执行得不差
3. **功能应该下沉**：它提供的价值其实是一个开关（行距、底色），不该占一个主题名额

进入候选之后，再看一个问题：**这个概念里还有没有没兑现的具体母题？** 有就是「需要重做」，没有就是「建议砍掉」。

举两个对照：`harvest`（金秋暖褐）和 `porcelain`（青花瓷韵）都是辨识度 2 分、都撞了 80% 以上的相似度。但「金秋暖褐」拆开来就是一组橙棕色值，重做一遍也还是那组色值；「青花瓷」则有缠枝纹、开光边框这些明确的视觉母题还没画。所以前者砍，后者重做。同理 `ink`（水墨）还有墨色浓淡和印章没做，判重做。

还有一种情况是概念有料但**赛道已经站满了**：`filmlog`（场记胶片）确实还有胶片孔、场记板条纹可挖，但砍完之后「档案」类仍保留 `sequence`、`gallery`、`scoreboard` 三套，而 `gallery` 和它共用同一副骨架（相似度 83.3%），加个深色变体就能覆盖。这种情况判砍。

## 二、逐套问题清单

### 编辑

**`magazine` 奢刊衬线 — 5 / 5 / 4 / 4 = 4.6｜保留精修**
全场执行最好的一套。行高 28px（正文 2.0 倍）是全场最舒展的档位之一；h1 上方 `EDITORIAL` 眉标、h2 上下双细线居中、h3 两侧破折号、引用块居中斜体配上下细线、表格只留天地线——整套是同一种「杂志内页」语汇，不是拼装。字号层级 1.92 / 1.34 / 1.16 也是全场前列。
问题：① 0 个局部 CSS 变量，14 种硬编码色值散落全文，改一次配色要全文替换；② 表格缺隔行底色，4 行以上的表会读串行；③ h3 的破折号在 375px 下和标题文字挤在一起，左右各只剩约 4px 间隙。

**`default` 编辑黑白 — 4 / 3 / 4 / 4 = 3.7｜保留精修**
作为出厂主题完成度合格：h1 居中配渐变短线、h2 米色圆角块配左竖条、表格黑色表头带隔行底色、代码块深色。
问题：① 主题叫「黑白」，但 h2 竖条、hr、列表符号全部吃 `--md-primary-color`，出厂默认是钴蓝——用户看到的第一眼是「黑白主题里插了三处蓝」；② h3 只比正文大 14%（15.96px vs 14px），靠一根下划线撑层级，在长文里 h3 容易被当成加粗段落；③ 提示块是基础样式的蓝黄配色，和米色＋黑的调性冲突，是整页最跳的两个色块。

**`press` 复古铅印 — 4 / 3 / 4 / 4 = 3.7｜保留精修**
米色纸底、h1 上下双线框、h2 双下划线，活字印刷的气质做出来了。
问题：① 与 `ink` 结构相似 75.5%，同属「奶油纸张族」（press / legal / xuan / harvest / eyecare 五套共用米色底＋深色文字的底子）；② h3 的左竖条用的是 `var(--md-primary-color)`，出厂默认渲染成钴蓝，在暖米色页面上是个孤立的冷色点；③ 缺隔行底色。

**`column` 专栏窄栏 — 2 / 1 / 4 / 4 = 2.5｜建议砍掉**
h1 是一行左对齐的加粗文字，没有任何处理——36 套里唯一一个 h1 完全裸奔的。h2、h3、引用块**全部是细左竖条**，宽度 3px / 3px / 2px，其中 h2 和引用块还是同一个蓝色（`--md-primary-color`），h3 是灰色。三种语义完全不同的块级元素只靠 1px 的宽度差和一次冷灰切换来区分，滑动时根本读不出层级。0 个伪元素装饰，与 `insight` 结构相似 76.5%，h3 只比正文大 8%。整套等于「default 去掉全部修饰」，没有任何值得保留的自有设计。

### 专业

**`launch` 产品发布 — 4 / 3 / 4 / 4 = 3.7｜保留精修**
h2 做成实色胶囊（inline-block 圆角药丸）是这套里唯一的自有手法，h1 渐变卡片、hr 收成一小段居中蓝线，收束感不错。
问题：① 与 `ocean` 结构相似 82.2%；② 胶囊 h2 的白字在中蓝底上只有约 5.6:1，14px 加粗勉强够用，但一旦用户把主色调浅就会失守；③ h3 只是浅灰底小条，和 h4 几乎无差别。

**`insight` 行业洞察 — 4 / 2 / 4 / 4 = 3.4｜保留精修**
执行干净：h2 整条深蓝实色块、表头同色、h1 深蓝下划线，专业稿的气质到位。
问题：① 0 个伪元素，与 `eyecare` 相似 79.5%、与 `swiss` 76.7%——它的「专业感」完全由深蓝这一个色相承担；② 与 `business`、`launch` 同属蓝色企业风，三套摆在一起用户说不出区别；③ h3 只比正文大 8%。建议它作为「专业」类唯一代表保留，把 business / finance 的可用元素并进来。

**`business` 执行简报 — 2 / 2 / 2 / 4 = 2.4｜建议砍掉**
**文件最薄的一套，120 行**，24 项排版元素里漏掉 7 项：`strong`、`em`、`ul/ol`、`li::marker`、`figcaption`、提示块及其标题行。这意味着粗体、斜体、列表符号、图注全部落回基础样式，主题只管了标题和表格。
h3 字号 14.28px，正文 14px——**只差 0.28px**，层级实质上不存在。视觉上是最典型的「蓝色企业模板」，与 insight / launch 三选一必然出局。

**`finance` 数据屏报 — 2 / 3 / 2 / 2 = 2.3｜建议砍掉**
h2 的做法是 `display:flex` + `::before` 画一个 0.95em 的方块，再用 `box-shadow: 1.1em 0 0` 在右边投出第二个淡色方块。**在 14px 下这两个方块读起来像渲染故障**，不像设计（截图里是「■ ■— 二、配图与分隔」）。而且 `display:flex` 和 `gap` 都是公众号会剥掉的属性，粘贴后两个方块会直接贴到文字上。
h3 = 14px = 正文字号，零层级。漏掉 `em`、`ul/ol`、`li::marker`、`figcaption`。深色 h1 卡片和深色引用块是这套仅有的亮点，可以并进 `insight`。

### 科技

**`cyber` 霓虹粗野 — 4 / 5 / 2 / 3 = 3.7｜保留精修**
辨识度全场前三：奶油底＋网格纹、h1 黑底白字块配偏移硬阴影、h2 蓝色实块、表格粗黑边框、h3 前缀 `//`。最近邻相似度只有 56.2%，是真的自成一格。
问题：① 完成度是硬伤，漏掉 `em`、`ul/ol`、`li::marker`、隔行底色、`figcaption`，粗野风的表格里居然没有隔行底色；② 提示块是柔和的蓝黄圆角卡片，和整页的硬边直角撞得很难看；③ 网格纹靠外层 section 的双层 `linear-gradient` + `background-size: 24px 24px` 平铺，**平铺完全依赖 `background-size`**，这条被剥掉网格就退化成一块纯奶油色，粗野感全失。

**`blueprint` 蓝图工程 — 4 / 3 / 3 / 1 = 2.9｜保留精修**
深蓝底＋虚线框＋网格，连表格单元格边框都是虚线，制图语汇贯彻得很彻底，是深色四套里最有说法的一套。
问题：① **提示块正文对比度 1.29:1，肉眼完全看不见**（详见共性问题 1）；② 与 `harvest` 结构相似 79.3%，说明骨架仍是那套通用骨架，只是换了虚线；③ 缺隔行底色。

**`terminal` 绿屏极客 — 3 / 4 / 3 / 1 = 2.9｜保留精修**
`$` 提示符开 h2、`>` 开 h3、绿色虚线 hr、近黑底——概念干净且只此一家。
问题：① **`$` 提示符默认渲染成钴蓝色**（`--md-primary-color`），一套绿屏终端主题的命令提示符是蓝的，这是肉眼可见的 bug，已在剪贴板产物中确认为 `color: #2851E3`；② h1 只比正文大 60%，是全场最扁的 h1，标题读起来不像标题；③ 提示块对比度 1.33:1，不可读。

**`tech` 深夜终端 — 3 / 2 / 2 / 1 = 2.1｜建议砍掉**
深色渐变底做得不难看，但它和 `nightread`、`blueprint`、`filmlog` 是同一个概念的四胞胎，而它是其中装饰最少的：0 个伪元素。
覆盖度倒数第三（漏 7 项：`em`、`ul/ol`、`li::marker`、隔行底色、`figcaption`、提示块×2）。提示块对比度 1.07:1，是全场最差。名字叫「深夜终端」，但真正有终端气质的是 `terminal`。

### 克制

**`academic` 研究论文 — 4 / 5 / 3 / 4 = 4.1｜保留精修**
**结构上最独特的一套，最近邻相似度只有 51.4%**。首行缩进 2em、`WORKING PAPER` 眉标、h2 自动编号、克制的横线，论文纸的质感是真做出来了。
问题：① **自动编号会和作者手写的编号撞车**——实测输出是 `1. 一、第一节`，而中文作者写「一、」是极常见的习惯，且没有开关可以关掉；② h3 = 14px = 正文字号，三级标题只剩加粗；③ 缺隔行底色。

**`swiss` 瑞士网格 — 4 / 3 / 4 / 4 = 3.7｜保留精修**
粗黑横线、严格直角、左对齐、粗 hr，国际主义风格执行得干净利落。
问题：① 与 `insight` 结构相似 76.7%，0 个伪元素——它的「瑞士感」几乎全靠 `border-top` / `border-bottom` 的粗细变化；② h3 只比正文大 4%；③ 和 `gallery` 争夺同一块「大量留白 + 无衬线 + 极简线条」的地盘。

**`minimalist` 留白日记 — 4 / 4 / 4 / 2 = 3.6｜保留精修**
`JOURNAL` 眉标、h2 上方一小段短线、引用块的大引号字符，克制得有分寸，最近邻只有 58.4%。
问题：① **对比度是硬伤**：正文 5.90:1 是全场倒数第三，提示块正文 3.91:1 达不到 WCAG AA 的 4.5:1，浅灰在手机户外基本读不清；② h2 上方那根短线用的是 `--md-primary-color`，默认钴蓝，和整套的暖灰调性不搭；③ 缺隔行底色。

**`eyecare` 护眼米黄 — 3 / 1 / 4 / 4 = 2.8｜建议砍掉**
行高 28.7px（2.05 倍）确实是全场最舒服的档位之一，护眼这个诉求是真的做到了。
但**「宽行距 + 米黄底」应该是两个开关，不是一整套主题**。与 `harvest` 结构相似 80.2%、与 `insight` 79.5%，0 个伪元素，除了行距和底色之外没有任何自有设计。它的价值应该以「阅读舒适度」预设的形式提供给全部主题。

### 氛围

**`legal` 琥珀手册 — 4 / 3 / 4 / 4 = 3.7｜保留精修**
`LEDGER` 眉标、h1 装在带边框的米色卡片里、琥珀色系、h2 上方短横线，商务叙事的暖调做得体面，最近邻 58.4% 也不算高。
问题：① 视觉上仍落在「奶油纸张族」里，和 press / xuan / harvest 一眼看去同一挂；② 眉标 `LEDGER` 是写死的英文，每篇文章的 h1 上都会顶着它，作者改不掉；③ 缺隔行底色。

**`aurora` 极光渐层 — 3 / 3 / 2 / 2 = 2.6｜建议砍掉**
**覆盖度全场最差，24 项里漏 8 项**：`strong`、`em`、`ul/ol`、`li::marker`、隔行底色、`figcaption`、提示块及标题行。粗体、斜体、列表符号、图注全部没管。
h1 用 `background-clip:text` 做渐变字。复制管线已经专门为它做了降级（复制前压成渐变第一个色标的纯色），所以不会消失——但这意味着**作者在预览里看到的渐变字和读者收到的纯色字不是一回事**，主视觉靠一个预览专属效果撑着。h3 = 14px = 正文字号。

**`mist` 晨雾微光 — 2 / 1 / 4 / 2 = 2.1｜建议砍掉**
**正文对比度 5.39:1，36 套里最低**。h2 是一块极浅的灰色渐变，和页面底色几乎分不开，滑动时会直接滑过标题。
与 `bloom` 结构相似 90.1%、与 `forest` 87.6%——它就是那套通用骨架刷成灰色。「通透」和「看不清」之间它站错了边。

**`nightread` 夜读深蓝 — 3 / 1 / 3 / 1 = 2.0｜建议砍掉**
深色四胞胎（tech / blueprint / nightread / filmlog）里说得最少的一套：0 个伪元素，唯一的手法是 h2 的蓝色左竖条。与 `eyecare` 结构相似 75.6%——一套深色主题和一套米黄主题骨架相似度这么高，本身就说明它没有为「夜读」做任何专门设计。
提示块对比度 1.77:1，不可读。行高 28.28px 是它唯一的优点，而这个优点属于「阅读舒适度」开关，不属于一套主题。

### 中式

**`vermilion` 朱砂古卷 — 4 / 4 / 4 / 4 = 4.0｜保留精修**
h2 用 `『』` 双引号包裹是全场最聪明的一个小手法，成本极低但一眼就是中式。朱红表头、米色卷面、红色分隔线，语汇统一。
问题：① 与 `porcelain` 结构相似 83.2%（两套中式共用一个骨架）；② **完全不使用 `--md-primary-color`**，用户在颜色选择器里选什么都不生效，这是个静默失效的产品控件；③ 缺隔行底色（表格是这套里最平的部分）。

**`xuan` 宣纸信笺 — 4 / 4 / 4 / 3 = 3.8｜保留精修**
横格纸底纹是全场唯一一个真正把「纸」做出来的设计，h1 两侧配破折号，虚线分隔，信笺感成立。
问题：① 横格靠外层 section 的 `linear-gradient` + `background-size: 100% 2.1em` 平铺，**行距完全由 `background-size` 决定**——这条一旦被剥，横格会退化成顶部孤零零一条线，整套主题塌成普通米色纸，这个风险需要单独验证；② 同样完全不用 `--md-primary-color`；③ 缺隔行底色。

**`ink` 水墨留白 — 4 / 2 / 4 / 3 = 3.2｜需要重做**
排版本身是全场最舒服的：行高 30.1px（2.15 倍，全场并列第一）、宽字距、居中 h1，长文阅读体验很好。
但**「水墨」这个概念完全没有落地**：没有墨色浓淡、没有晕染、没有印章、没有笔触，CSS 里就是灰色文字加一根短横线。与 `press` 结构相似 75.5%，本质是「米白纸上的克制排版」，换个名字叫「素笺」也完全说得通。更糟的是它唯一的装饰（h1 下的短线）吃 `--md-primary-color`，默认渲染成钴蓝——一套水墨主题顶着一根蓝线。概念可以保留，执行要重来。

**`porcelain` 青花瓷韵 — 4 / 2 / 4 / 4 = 3.4｜需要重做**
干净、对比度健康、表格清爽，但「青花瓷」只体现在色相上。0 个伪元素，与 `vermilion` 结构相似 83.2%。放在 `insight`、`ocean`、`blueprint` 旁边，用户只会觉得「又一个蓝色主题」。
要么把青花的缠枝纹、开光边框这类具体母题做出来，要么就并进 `insight`。它是本轮最接近砍掉线的「保留」项。

### 自然

这一类是**「只换了个颜色」最赤裸的证据**。四套的 CSS 骨架几乎逐行对应：`section` 定义 5 个局部变量 → h1 居中 → h2 `border-left: 6px` + `border-radius: 0 12px 12px 0` + 浅色块 → h3 变色 + 下划线 → `p,li` 变色 + 行高 → `ul,ol padding-left: 1.55em` → `li::marker` → 引用块左竖条 + 浅底 → 代码块圆角 → 表格 `border-collapse: separate` + 实色表头 + `nth-child(even)` → `a` 下划线 → `strong` / `em` → `img` 圆角阴影 → `figcaption` → `hr` 渐变。

**`bloom` 花期柔粉 — 4 / 2 / 4 / 3 = 3.2｜保留精修**
四套里唯一做了差异化的：h2 是粉色胶囊而不是左竖条。建议作为「自然 / 柔和」类的唯一代表保留，并改造成消费 `--md-primary-color`，让颜色选择器接管其余三套的功能。与 `mist` 相似 90.1%。

**`harvest` 金秋暖褐 — 4 / 2 / 4 / 4 = 3.4｜建议砍掉**
执行不差，暖褐＋米色纸的搭配也舒服，但它同时踩中两个重复族：与 `eyecare` 结构相似 80.2%（奶油纸张族第五套），骨架又是自然类那一套。press / legal / xuan 三套已经把暖色纸面覆盖完了。

**`forest` 松林深绿 — 4 / 1 / 4 / 4 = 3.1｜建议砍掉**
与 `mist` 相似 87.6%、与 `default` 83.9%、与 `ocean` 80.0%。唯一的装饰是 h1 下的一根短线，而它吃 `--md-primary-color`——**一套松林深绿主题，出厂默认在标题下画一根钴蓝色的线**（已在计算样式中确认为 `rgb(40, 81, 227)`）。

**`ocean` 海盐微蓝 — 4 / 1 / 4 / 4 = 3.1｜建议砍掉**
**与 `sunrise` 结构相似度 91.7%，是全部 630 个主题对里最高的一对**。两套文件的区别只有色值。0 个伪元素。

### 活力

**`pop` 波普撞色 — 5 / 5 / 4 / 3 = 4.4｜保留精修**
**设计语言贯彻得最彻底的一套**。黑 / 柠檬黄 / 品红三色，硬边偏移阴影同时用在 h1、h2、引用块、代码块、图片、表格上，连 hr 都是黑黄相间的虚线段。每一个元素都在说同一句话，这在 36 套里是独一份。最近邻 69.5%。
问题：① 整套辨识度**押在 `box-shadow` 偏移块上**，公众号通常保留 box-shadow，但一旦被剥，这套主题会瞬间变成普通的黑黄配色，需要单独做降级验证；② 提示块的柔和蓝黄圆角卡片和整页的硬边撞色格格不入，是唯一的破绽。

**`neon` 荧光夜行 — 4 / 3 / 4 / 1 = 3.1｜保留精修**
青紫渐变胶囊 h2、发光标题、暗紫底，潮流感做出来了。
问题：① **提示块对比度 1.48:1，不可读**；② 发光效果靠 `text-shadow`，是公众号可能剥掉的属性，剥掉之后就是一套普通的暗色主题；③ 与 `blueprint` 结构相似 76.0%。

**`candy` 糖果手账 — 3 / 3 / 4 / 2 = 3.0｜保留精修**
虚线语汇（h1 虚线框、引用块虚线、hr 虚线）配珊瑚色胶囊 h2，手账感成立且统一。
问题：① **对比度全线偏软**：正文 5.79:1、提示块 4.66:1 刚过线、h2 胶囊是白字压浅珊瑚；② 与 `ocean` 结构相似 85.4%，虚线之外的骨架还是通用那套；③ 虚线在 375px 下密度偏高，四条虚线同屏时页面显得毛躁。

**`sunrise` 晨曦渐暖 — 4 / 1 / 4 / 4 = 3.1｜建议砍掉**
与 `ocean` 91.7% 结构相同（见上）。橙粉渐变的 h1 和表头是它仅有的个性，而这两处完全可以由 `bloom` 加颜色选择器实现。0 个伪元素。

### 档案

**`sequence` 编号索引 — 4 / 4 / 3 / 4 = 3.8｜保留精修**
`INDEX` 眉标 + h2 上方一个大号自动序号，教程 / 方法论场景下确实好用。字号层级 1.96 / 1.32 / 1.10 是全场最健康的之一，编号在复制后会固化成字面文本（实测 `1`、`2`），不会丢。

**`gallery` 展签白盒 — 3 / 4 / 4 / 4 = 3.7｜保留精修**

问题：① **层级是全场最扁的**：h1 是全场第二大（正文的 1.98 倍），但 h2 只有 1.20 倍、h3 只有 1.02 倍——巨大的标题之下，二级、三级、正文几乎同一个字号，长文里完全找不到结构；② 与 `filmlog` 结构相似 83.3%（两套共用「眉标 + 小标签」骨架）；③ `EXHIBIT` 是写死的英文标签，每个 h2 前都会出现。

**`scoreboard` 赛报计分 — 4 / 4 / 3 / 1 = 3.2｜保留精修**
**字号层级全场最好**：h1 是正文的 2.02 倍、h2 是 1.36 倍、h3 是 1.10 倍，是唯一一套三级都拉开了的主题。`REPORT` 斜体眉标、`NO.1` 序号徽章、列表隔行左竖条、黑底引用块，赛报的气质很足。

**`filmlog` 场记胶片 — 4 / 2 / 3 / 1 = 2.6｜建议砍掉**
`SCENE LOG` / `SCENE` 标签、虚线、等宽字体点缀，场记板的概念执行得完整，单看画面是好看的。
辨识度只给 2 分是因为**它的个性完全由两个已经很拥挤的手法拼成**：眉标是 7 套主题共用的招（minimalist / academic / legal / sequence / gallery / scoreboard 都在用），深色蓝是 4 套共用的底（tech / blueprint / nightread）。与 `gallery` 结构相似 83.3%，两者其实是同一副骨架的明暗两版。再加上提示块对比度 1.11:1 不可读、`SCENE` 标签写死英文顶在每个 h2 前。真正属于胶片的母题（片孔、齿孔条、场记板斜纹）一个都没做，而这些完全可以作为 `gallery` 的深色变体补上。

## 四、共性问题汇总（按影响面排序）

### 1. GFM 提示块：36/36 全都没管，其中 7 套的正文肉眼不可见 — 影响面 36/36

**36 套主题没有一套写过 `markdown-alert` 相关的样式**，全部落回 `base.css` 的统一蓝 / 绿 / 黄 / 红。后果分两层：

**审美层**：任何主题里插一个提示块，都会突然冒出一块和主题配色无关的浅蓝或浅黄卡片。在 `cyber`（硬边撞色）、`pop`（黑黄品红）、`swiss`（黑白粗线）这类风格强烈的主题上尤其刺眼。

**可读性层——这是硬故障**。根因是：GFM 提示块的 DOM 就是 `<blockquote class="markdown-alert ...">`。主题为自己的引用块设计写了 `blockquote { color: ... }` 或 `blockquote p { color: ... }`，这条规则会被提示块继承；但提示块的背景由 `base.css` 的 `#output .markdown-alert-note`（一个 class 选择器）设定，特异性更高，主题的背景覆盖不掉。于是**主题的文字色 + 基础样式的背景色**撞在一起：

| 主题 | 提示块正文对比度 | 主题给 blockquote 的字色 | 现象 |
| --- | --- | --- | --- |
| `tech` | **1.07 : 1** | `rgb(230,237,248)` 近白 | 整段消失 |
| `scoreboard` | **1.10 : 1** | `#fff`（服务它自己的黑底引用块） | 整段消失，且这是套**浅色主题** |
| `filmlog` | **1.11 : 1** | `rgb(240,232,219)` 米白 | 整段消失 |
| `blueprint` | **1.29 : 1** | `rgb(196,220,240)` 浅蓝 | 整段几乎不可读 |
| `terminal` | **1.33 : 1** | `rgb(183,223,194)` 浅绿 | 整段几乎不可读 |
| `neon` | **1.48 : 1** | `rgb(207,198,234)` 浅紫 | 整段几乎不可读 |
| `nightread` | **1.77 : 1** | `rgb(174,187,210)` 浅灰蓝 | 吃力可辨，仍远低于可用线 |
| `minimalist` | 3.91 : 1 | `rgb(122,122,122)` 中灰 | 未达 WCAG AA 4.5:1 |
| `candy` | 4.66 : 1 | `rgb(119,105,127)` 灰紫 | 勉强及格 |

注意 `scoreboard` 是**浅色主题**也中招——这不是「深色主题的问题」，是所有给 `blockquote` 设过文字色的主题的问题。

**系统性解法**：在 `base.css` 里给提示块补一条明确的文字色（不要依赖继承），并把提示块的配色开放成主题可覆写的一组 CSS 变量（`--alert-accent` / `--alert-border` / `--alert-background` 已经存在，缺的是 `--alert-foreground`）。这样一处修改同时解决 36 套的审美问题和 7 套的可读性事故。

### 2. 主色与主题脱钩，导致「串色」和「颜色选择器失效」两种相反的病 — 影响面 36/36

切换主题**不会**改变主色（`useThemeStore` 里 `theme` 和 `primaryColor` 是两个独立的持久化字段，切主题只重新 `applyTheme`，不动 `primaryColor`）。出厂默认是钴蓝 `#2851E3`，于是 36 套主题开箱全部共享同一个强调色。各主题对这个变量的态度又完全不一致：

| 引用次数 | 主题数 | 后果 |
| --- | --- | --- |
| 9–12 次（主色主导外观） | 7 套：`default`、`business`、`aurora`、`sequence`、`filmlog`、`gallery`、`scoreboard` | 这几套默认全是蓝的，摆在一起像同一套主题的变体 |
| 6–8 次 | 1 套：`cyber` | 主色与主题色平分秋色，尚可接受 |
| 2–5 次 | 11 套：`magazine`、`press`、`column`、`finance`、`insight`、`launch`、`tech`、`minimalist`、`academic`、`swiss`、`legal` | 部分**串色** |
| **1 次** | 7 套：`blueprint`、`terminal`、`eyecare`、`mist`、`nightread`、`ink`、`forest` | **最糟的一档**：孤零零一处钴蓝，必然显眼且必然违和 |
| 0 次 | 10 套：`vermilion`、`xuan`、`porcelain`、`ocean`、`bloom`、`harvest`、`candy`、`pop`、`neon`、`sunrise` | **颜色选择器完全失效**，用户改颜色没有任何反应 |

「用 1 次」这一档已确认的实例：

- `terminal`（绿屏极客）的 `$` 命令提示符渲染成 **`#2851E3` 钴蓝**（剪贴板产物中确认）
- `forest`（松林深绿）h1 下的短线渲染成 **`rgb(40, 81, 227)` 钴蓝**
- `minimalist`（暖灰调）h2 上方的短线同样是钴蓝
- `ink`（水墨留白）唯一的墨线也是钴蓝

**系统性解法**：给每套主题定义一个 `defaultPrimaryColor`，切主题时把主色带过去（用户手动改过的话再另说）；同时统一规范——要么全套消费 `--md-primary-color`，要么明确声明这套主题不接受调色并在 UI 上禁用颜色选择器。目前这种一半用一半不用的状态，两边的用户预期都落空了。

### 3. 标题层级被压扁，h3 中位数只比正文大 6% — 影响面 36/36

统一 14px 正文下的实测字号比：

| 层级 | 中位数 | 最小 | 分布 |
| --- | --- | --- | --- |
| h1 / 正文 | 1.73 | 1.50（`academic`） | 1.50 – 2.02 |
| h2 / 正文 | 1.24 | 1.18（`candy`） | 1.18 – 1.36 |
| **h3 / 正文** | **1.06** | **1.00** | **1.00 – 1.16** |

**h3 = 正文字号（比值 1.00）的有 5 套**：`finance`、`tech`、`academic`、`aurora`、`legal`。这些主题的三级标题只靠加粗和变色区分，在滑动阅读里读者会直接把它当成一个加粗段落。

h2 的分布同样过窄——36 套全部挤在 1.18–1.36 之间，也就是说所有主题的二级标题都是 16.5–19px。公众号长文里 h2 是最重要的结构锚点，这个区间偏保守。

反例值得抄：`scoreboard`（2.02 / 1.36 / 1.10）和 `sequence`（1.96 / 1.32 / 1.10）是仅有的把三级都拉开的两套，读起来结构感明显更强。

**系统性解法**：定一条全局字号阶梯基线（例如 h1 ≥ 1.8、h2 ≥ 1.3、h3 ≥ 1.12），作为主题验收的硬指标，允许个别主题为风格破例但必须显式说明。

### 4. 一副骨架换色：最高结构相似度 91.7%，14 套共用同一套 CSS 结构 — 影响面 ~20/36

只比较「哪个选择器声明了哪些属性」（丢掉全部色值和尺寸），得到的相似度前十：

| 主题对 | 结构相似度 |
| --- | --- |
| `ocean` ↔ `sunrise` | **91.7%** |
| `mist` ↔ `bloom` | 90.1% |
| `mist` ↔ `forest` | 87.6% |
| `ocean` ↔ `candy` | 85.4% |
| `forest` ↔ `bloom` | 84.9% |
| `default` ↔ `forest` | 83.9% |
| `filmlog` ↔ `gallery` | 83.3% |
| `vermilion` ↔ `porcelain` | 83.2% |
| `candy` ↔ `sunrise` | 82.6% |
| `launch` ↔ `ocean` | 82.2% |

共用的那副骨架是：`section` 定义 4–5 个 `--theme-*` 变量 → h1 居中/卡片 → **h2 `border-left` 竖条 + `border-radius: 0 Npx Npx 0` + 浅色块** → h3 变色加下划线 → `p,li` 变色 → `li::marker` → 引用块左竖条 + 浅底 → 表格 `border-collapse: separate` + 实色表头 + `nth-child(even)` → `a` 下划线 → `img` 圆角阴影 → `hr` 渐变。

**22 / 36 套的标题在用 `border-left` 竖条**，24 / 36 套在用「整块底色」。这两个手法叠在一起就是上面那副骨架。

**系统性解法**：把这副骨架抽成一层可配置的基础模板（竖条宽度、圆角、色块深浅、表头样式全部参数化），主题只写自己真正独有的部分。这样一来「自然类四套」这种需求，本来就该由「一套模板 + 四组色板」实现，而不是四个 160 行的 CSS 文件。

### 5. 装饰手法贫乏且分布极不均：18 套零伪元素，19 套缺表格隔行底色 — 影响面 18–19/36

**伪元素装饰**（`::before` / `::after`，辨识度的硬指标）：

- 0 处：**18 套** — `press`、`column`、`business`、`insight`、`launch`、`tech`、`blueprint`、`swiss`、`eyecare`、`aurora`、`nightread`、`porcelain`、`ocean`、`harvest`、`candy`、`pop`、`neon`、`sunrise`
- 1–2 处：14 套
- 3–4 处：4 套（`magazine` 4、`minimalist` 3、`xuan` 3）

需要澄清一点：**伪元素装饰是能活着穿过复制管线的**。已实测确认 juice 的 `inlinePseudoElements: true` 会把它们实体化成带内联样式的 `<span>`，CSS 计数器也会固化成字面文本（`academic` → `1. `，`scoreboard` → `NO.1`）。也就是说这条路是通的，18 套主题只是**没用**，不是不能用。

其余覆盖度缺口：

| 缺失元素 | 主题数 | 说明 |
| --- | --- | --- |
| 提示块样式 | **36 / 36** | 见共性问题 1 |
| 提示块标题行 | **36 / 36** | 图标与标题的配色全部沿用基础样式 |
| 表格隔行底色 | **19 / 36** | 4 行以上的表格容易读串行 |
| `em` 斜体 | 5 / 36 | `business`、`finance`、`tech`、`cyber`、`aurora` |
| `ul` / `ol` 缩进 | 5 / 36 | 同上 |
| `li::marker` | 5 / 36 | 同上；列表符号落回浏览器默认 |
| `figcaption` 图注 | 5 / 36 | 同上；图注是公众号高频元素 |
| `strong` 粗体 | 2 / 36 | `business`、`aurora` |

`business`、`finance`、`tech`、`cyber`、`aurora` 这五套是同一批「只管了标题和表格」的半成品，缺口高度重合。

### 附：其他值得记一笔的问题

- **自动编号与作者手写编号撞车**：`academic` 实测输出 `1. 一、第一节`，`sequence` 输出 `1一、第一节`（连分隔符都没有）。中文作者写「一、」「1.」是常见习惯，这两套主题没有任何开关可以关掉自动编号。`scoreboard` 的 `NO.x` 徽章因为语义上是「第几条」而不是「章节号」，撞车没那么难看。
- **写死的英文眉标**：`minimalist` 的 `JOURNAL`、`academic` 的 `WORKING PAPER`、`legal` 的 `LEDGER`、`sequence` 的 `INDEX`、`filmlog` 的 `SCENE LOG` / `SCENE`、`gallery` 的 `CATALOGUE` / `EXHIBIT`、`scoreboard` 的 `REPORT`——7 套主题在每篇文章的标题上顶着一个作者改不掉的英文词。这本身也是一种同质化手法（7 套都在用「眉标」这一招）。
- **配色组织混乱**：`magazine` 是唯一一套 **0 个局部变量**的主题，14 种色值全部硬编码，最难维护。整体来看局部变量数中位数是 5 个，而硬编码色值中位数是 13 种——也就是说大部分主题的「变量体系」只罩住了少数几个基础色，其余全靠散落的字面量，改一次配色要在文件里全文搜索替换。
- **依赖会被剥离的属性**：`finance` 的 h2 依赖 `display:flex` + `gap`；`pop` 的整套辨识度押在 `box-shadow` 偏移块上；`neon` 的辉光依赖 `text-shadow`；`cyber` 和 `xuan` 的底纹依赖外层 section 的 `linear-gradient` + `background-size` 平铺。这四类都需要单独做一次「剥掉之后长什么样」的降级验证——现有的 `scripts/verify-wechat-layout.mjs` 已经有成熟的「剥属性后重新测量」框架，可以直接扩展。

## 六、优先级建议

### 最值得优先打磨的 5 套

| 排序 | 主题 | 理由 |
| --- | --- | --- |
| 1 | `magazine` 奢刊衬线 | 全场执行最好（4.6），最近邻相似度仅 53.1%。只要补上局部变量体系和表格隔行底色，就是可以直接对外宣传的旗舰款 |
| 2 | `pop` 波普撞色 | 设计语言贯彻最彻底的一套，六类元素说同一句话，这在 36 套里独一份。优先要做的是 `box-shadow` 被剥后的降级验证 |
| 3 | `academic` 研究论文 | 结构上最独特（最近邻 51.4%），首行缩进＋自动编号是真正的差异化能力。修掉编号撞车和 h3 层级即可 |
| 4 | `scoreboard` 赛报计分 | 字号层级全场最好（2.02 / 1.36 / 1.10），应当作为其他主题的层级基准。但必须先修掉那个白字压浅蓝底的提示块事故 |
| 5 | `vermilion` 朱砂古卷 | `『』` 是全场性价比最高的辨识手法，成本极低效果极好。改造成消费主色之后，可以顺势承接被砍掉的中式配色需求 |

### 最该砍的 5 套

| 排序 | 主题 | 理由 |
| --- | --- | --- |
| 1 | `nightread` 夜读深蓝 | 2.0 分垫底。深色四胞胎里说得最少（0 伪元素），骨架却和米黄主题 `eyecare` 相似 75.6%，提示块不可读。它唯一的优点（宽行距）属于开关而非主题 |
| 2 | `mist` 晨雾微光 | 正文对比度 5.39:1 全场最低，h2 与底色几乎融合；与 `bloom` 结构相似 90.1%。「通透」做成了「看不清」 |
| 3 | `ocean` 海盐微蓝 | 与 `sunrise` 结构相似 **91.7%，全场最高的一对**，两个文件的差别只有色值。这一对是「数量虚胖」最干净的证据 |
| 4 | `business` 执行简报 | 120 行的半成品，24 项里漏 7 项，h3 只比正文大 0.28px；与 insight / launch 同质，三选一必然出局 |
| 5 | `column` 专栏窄栏 | 唯一 h1 完全无处理的主题，h2 / h3 / 引用块共用同一根蓝竖条导致元素无法区分，0 伪元素。它就是「default 去掉修饰」，不存在保留价值 |

### 收敛路线建议

三条系统性修复应当**先于**任何单套主题的打磨，因为它们一次改动同时惠及全部主题：

1. 补 `--alert-foreground` 并把提示块配色开放给主题覆写 — 一次修复 36 套的审美问题和 7 套的可读性事故
2. 给每套主题定义 `defaultPrimaryColor` 并统一主色消费规范 — 消除串色和颜色选择器静默失效
3. 抽出参数化的基础骨架层（竖条 / 色块 / 表头 / 圆角） — 让「换色」这件事回到颜色选择器，主题文件只写真正独有的部分

做完这三条之后再砍 13 套、精修 5 套，36 → 23 的收敛才是净收益而不是功能缩水。
